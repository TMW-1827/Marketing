# Зведення мотивацій дистриб'юторів ТМ Трускавецька

Перевіряє щомісячні файли дистриб'юторів на коректність заповнення і — лише
після того, як розбіжності розібрані, — вносить місяць у зведену таблицю.

Порядок роботи навмисне двоступеневий: спершу `validate` показує, що не так,
далі людина виправляє джерела, і тільки потім `apply` записує підтверджені
дані. Сам інструмент джерел не редагує.

## Як відкрити

**З браузера, нічого не встановлюючи:**

<https://tmw-1827.github.io/Marketing/motivation-consolidation/web/>

Сторінка статична, сервера за нею немає. Уся обробка Excel відбувається
просто у вкладці: [Pyodide](https://pyodide.org) запускає в браузері той
самий пакет `mc`, що й командний рядок. **Файли нікуди не
завантажуються** — ані на GitHub, ані кудись іще; вони живуть лише в
пам'яті вкладки, доки її не закрити.

Єдине, що тягнеться ззовні — саме середовище Python (близько 13 МБ з
cdn.jsdelivr.net, браузер його кешує). Бібліотеки для Excel лежать
поруч у репозиторії, тож PyPI під час роботи не потрібен.

**Локально, без інтернету:**

```bash
python -m mc.web
```

Відкриється те саме, але з локального сервера. Щоб обійтися й без CDN,
поклади поруч розпакований Pyodide і додай його адресу до посилання:
`?pyodide=/.pyodide-local/`.

Для командного рядка (нижче) знадобиться `pip install -r requirements.txt`;
для роботи через браузер — ні.

## Порядок роботи

1. **Один раз завантажити зведену таблицю.** Саме в неї дописуються нові
   місяці. Копія лишається у вкладці до кінця роботи.
2. **Перетягнути файли дистриб'юторів** (можна всі одразу). Система сама
   визначає, чий це файл і за який місяць, і одразу показує перевірку.
3. **Подивитись картки.** Зелена — готово, жовта — є попередження, червона —
   потребує виправлення. Під кожною видно розібрані цифри, звірку мотивації
   з умовами і перелік зауважень із посиланням на клітинку.
4. **Натиснути «Внести у зведену»** — зʼявиться вікно з переліком того, що
   саме буде записано. Без підтвердження в цьому вікні у файл не потрапляє
   нічого.
5. **Завантажити оновлену зведену.** Обов'язково: у браузерній версії
   файл існує лише у вкладці, і закриття сторінки його втрачає.

Один файл зазвичай приносить дві речі — факт місяця, що завершився, і план
на наступний. Вони показуються окремими картками, бо закрити місяць і
відкрити новий це різні дії.

Коли підтверджується перший файл із планом на місяць, якого у зведеній ще
немає, система:

* дорощує попередній місяць з 5 до 8 колонок (факт, бонус факт, приріст
  факту, затратність);
* створює заготовку нового місяця;
* переносить у неї **умови акцій із планового аркуша**.

Оригінал зведеної на диску не змінюється: система працює з копією в
пам'яті вкладки, а результат ти зберігаєш сам.

Порт локального сервера змінюється змінною `MC_PORT` (типово 8000).

## Командний рядок

```bash
# 1. перевірити всі файли за місяць
python -m mc validate /шлях/до/файлів -c зведена.xlsx -p 2026-07

# 2. подивитись, що буде записано (без запису)
python -m mc apply /шлях/до/файлів -c зведена.xlsx -p 2026-07

# 3. записати
python -m mc apply /шлях/до/файлів -c зведена.xlsx -p 2026-07 --confirm

# записати лише тих, хто вже в порядку, поки решта виправляється
python -m mc apply ... --confirm --only "ТОВ ГалаТеа" "Олга Торг"

# заразом перебудувати діапазони в рядках «Сума»
python -m mc apply ... --confirm --fix-totals

# не чіпати оригінал
python -m mc apply ... --confirm --out зведена_нова.xlsx
```

Якщо `-p` не вказано, береться найсвіжіший місяць, для якого факт-аркуші є
щонайменше в половини файлів.

`apply` без `--confirm` нічого не записує. З `--confirm` він відмовляється
писати, поки лишається хоч одна помилка рівня ✗ — обійти це можна лише
явним `--only`.

## Звірка мотивації з умовами

Мотивація рахується за умовами, які записані текстом під таблицею
(«Задачі на місяць / мотивації ТП»). Система розбирає цей текст і
перераховує бонус кожного рядка окремо.

Підтримувані формулювання:

| Вигляд умови | Приклад |
|---|---|
| ставка за одиницю | `ТП - 0,85 грн./пл., СВ - 0,15 грн./пл.` |
| ставка з порогом і половинним бонусом | `тп - 0,7 грн/пл. при виконанні 100%, від 70% до 99% - бонус 50%, до 70% - не виплачується` |
| ставка з підвищенням | `120% - Бонус ТП 1,5 грн/пл` |
| фіксована сума зі сходинками | `тп - 1800, св 2500 при виконанні на 96% і більше; при виконані 80-95 % - тп - 900` |
| сума з альтернативою | `бонус 1000 грн за виконання на 100 %, або 500 грн за 80-99%` |
| сходинки на кожну роль | `_ТП_ при виконанні від 85 % - 90% - 2500 грн, 91% - 99% - 3000 грн` |

Якщо в одного дистриб'ютора два завдання (вал і АКБ), умови діляться за
пунктами і кожен блок звіряється зі своїм.

На плановому аркуші факту ще немає, тому плановий бонус звіряється з
умовами **при 100 % виконання** — саме так його і рахують.

Там, де впевненого розбору не вийшло, система каже про це прямо
(«ставка задана в грн/пл, а блок веде облік у ТТ», «умови не розібрано»)
і не вигадує цифру.

## Що перевіряється

**Структура**

| Код | Рівень | Про що |
|-----|--------|--------|
| S0 | ✗ | дистриб'ютора немає в `config/distributors.yaml` |
| S1 | ✗ | немає аркуша «план» за місяць |
| S2 | · | немає аркуша «факт» — місяць вноситься лише плановою частиною |
| S3 | ! | заголовок аркуша суперечить його назві (копіпаст з іншого місяця) |
| S4 | ✗ | не розпізнано жодної таблиці мотивацій |
| S5 | · | блок без сум мотивації — у зведену не потрапляє |
| S6 | · | таблиця в план-аркуші вже має факт — це довідка за минулий місяць |

**Арифметика**

| Код | Рівень | Про що |
|-----|--------|--------|
| A1 / A2 | ✗ | план / факт у підсумковому рядку не дорівнює сумі рядків ТП |
| A3 | ! | підсумок мотивації не сходиться із сумою по рядках |
| A4 | ! | у клітинці «%» стоїть не те, що дає факт/план |

**План: потрійна звірка**

| Код | Рівень | Про що |
|-----|--------|--------|
| P1 | ✗ | план у факт-аркуші ≠ план у план-аркуші того самого місяця |
| P3 | ! | склад команди змінився між планом і фактом |
| B0 | ! | плановий бонус у джерелі порожній — клітинку буде лишено незаповненою |
| C2 | ✗ | значення у зведеній ≠ значення в джерелі |
| C0 | ✗ | у зведеній немає рядка під цю метрику |
| C3 | ! | у зведеній немає факту за попередній місяць — приріст нема від чого рахувати |

**Акції (Блок 2)**

| Код | Рівень | Про що |
|-----|--------|--------|
| Q1 | ✗ | залишок ≠ вхідний + прихід − витрата |
| Q2 | ✗ | залишок не сходиться із залишком попереднього місяця |
| Q3 | ✗ | вхідний залишок ≠ вихідному за попередній місяць |
| Q4 | ! | від'ємний залишок акційної продукції |
| Q5 | ! / · | блоку акцій не знайдено (для кого це норма — вказано в конфігу) |

**Здоровий глузд**

| Код | Рівень | Про що |
|-----|--------|--------|
| N1 | ! | виконання плану поза коридором 30–200 % |
| N2 | ! | затратність на одиницю різко вибивається з медіани за пів року |

**Мотивація проти умов**

| Код | Рівень | Про що |
|-----|--------|--------|
| M1 | ! | бонус у файлі не збігається з тим, що дають умови під таблицею |
| M3 | · | умови не вдалося розібрати або вони незастосовні до цього блоку |

## Як приймається рішення, чи брати блок у зведену

За сумою мотивації. Якщо в блоці немає ненульових бонусів — він у зведену не
йде. Саме тому київська команда Алекс ком (ЕК) відсіюється автоматично: її
продажі є, а мотивації немає. Щойно в таблиці з'являться суми мотивації —
блок почне враховуватись без жодних змін у коді.

Три метрики відповідають трьом таблицям зведеної: продажі (пляшки/шт), АКБ
(торгові точки), сума ВП (гривні). Дистриб'ютор може бути одночасно в
кількох (Буковина Трек Чернівці — у продажах і в АКБ) і може між ними
переходити (Бойчак свого часу мотивувався від % валових продаж, зараз — від
продажів).

## Як влаштована зведена

Місяці йдуть блоками колонок зліва направо, дата місяця — у рядку 2 над
першою колонкою блоку.

* **закритий місяць — 8 колонок**: план, факт, бонус план, бонус факт,
  план приріст %, факт приріст %, форма компенсації, затратність (факт);
* **поточний місяць — 5 колонок**: план, бонус план, план приріст %,
  затратність (план), умови акцій.

Тому `apply` робить дві дії: дорощує попередній блок з 5 до 8 колонок і
додає праворуч новий на 5. Колонка «Умови акцій» у закритому місяці не
передбачена — її текст при закритті втрачається, тому програма про це
окремо попереджає.

Оформлення нових колонок не вигадується: кожна бере формат, межі, шрифт
і ширину з колонки тієї самої ролі в попередньому місяці. Це важливо саме
при закритті, бо колонки міняють призначення — там, де був плановий бонус,
стає факт, а на місці «Умови акцій» — приріст.

Якщо місяць закривається без факту, система про це попереджає **до**
запису: приріст наступного місяця рахується саме від нього.

Приріст рахується від **факту** попереднього місяця:
`План приріст = План(M) / Факт(M−1) − 100%`.

## Конфіг

`config/distributors.yaml` — відповідність назв («Адк Ллір» у джерелі →
«АДК ЛЛІР / НЕОШ-М» у зведеній), пороги перевірок і позначка, чи веде
дистриб'ютор облік залишків акційної продукції.

Виграє найдовший збіг, тому «Буковина Трек ІФ» не плутається з
«Буковина Трек».

Новий дистриб'ютор = один запис у цьому файлі + рядок у зведеній.

## Чому розбір такий обережний

Файли-джерела заповнюють різні люди, і розкладка гуляє: заголовок таблиці
починається то з `B7`, то з `C10`; колонка «факт» буває `D`, `E`, `F` або
`G`; назви аркушів написані шістьма схемами (`план січень 24`,
`Січень 2026 план`, `03`, `3`, `план липень 26р БОЙЧАК`) і містять
одруківки та неправильні роки.

Через це:

* період береться із заголовка **всередині** аркуша, а не з його назви;
  якщо заголовок дублює вже зайнятий місяць або тягне період назад —
  спрацьовує назва аркуша, і система про це попереджає;
* колонки шукаються за текстом шапки, а не за фіксованими адресами;
* підсумкові рядки визначаються за підписом ролі (СВ / НТО / НТВ / КТВ /
  Всього), а якщо так підсумку не видно — запасним арифметичним способом;
* сума мотивації шукається як клітинка, що дорівнює сумі бонусів над нею —
  підпис у неї в різних файлах різний, а буває, що його немає взагалі.

## Як це зібрано

```
mc/            розбір і перевірка — спільні для браузера й командного рядка
  service.py   шар, який викликають обидва інтерфейси
  web.py       локальний файловий сервер
web/           сторінка: index.html + app.js + style.css
  vendor/      openpyxl, et_xmlfile, xlrd, yaml одним архівом (397 КБ)
tools/         build_vendor.py — перезбирає цей архів із PyPI
config/        distributors.yaml
```

Сторінка забирає модулі `mc/*.py` і конфіг просто з репозиторію, тож
виправлення в перевірках одразу діє і в браузері — окремої збірки немає.

Оновити вкладені бібліотеки:

```bash
python tools/build_vendor.py
```

## Тести

```bash
python -m pytest tests/ -q
```

Перевірено наскрізно у справжньому браузері: зі зведеної, обрізаної на
червні, сторінка з 15 файлів відтворила липень — усі 16 планів збіглися
з внесеними вручну, умови акцій перенеслися для всіх рядків. Розбір
15 файлів (сумарно 30 МБ) займає близько 13 секунд.
