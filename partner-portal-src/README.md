# Зовнішній портал ТМ «Трускавецька»

Публічний портал для тих, з ким працює бренд: дистриб'юторів, торговельних
мереж, закладів HoReCa, кінцевих споживачів і партнерів спонсорських проєктів.

Зроблений на основі внутрішнього навчального порталу (`training-portal-src`):
та сама дизайн-система, та сама модель контенту, ті самі віджети каталогу й
логістики. Відрізняється аудиторією і, головне, тим, чого тут **немає**.

## Що всередині і чого немає

**Є:**

- **Вода** — головна, склад і властивості, джерело й Трускавець, три лінійки,
  каталог форматів. Це основний акцент порталу.
- **Співпраця** — дистриб'юторам, мережам, HoReCa, логістика, якість і документи.
- **Спонсорство** — що ми підтримуємо, що даємо як спонсор, як подати заявку.
- **Довідка** — споживачам (з блоком питань і відповідей), матеріали бренду,
  довідник зі штрих-кодами й глосарієм, контакти.

**Свідомо немає:**

- цін, знижок, РРЦ, цінових зон, калькулятора націнки;
- обсягів, строків і умов постачання;
- внутрішніх матеріалів: тесту, сертифіката, скриптів продажу, роботи із
  запереченнями, обліку прогресу, входу за акаунтом.

Правило просте: у порталі лишається тільки те, що не змінюється від дати й від
контрагента. Усе комерційне узгоджується в договорі. Тому в моделі даних
(`src/types/catalog.ts`) немає навіть поля для ціни — зовнішній портал не може
її показати навіть помилково.

## Один слоган

Слоган бренду в зовнішній комунікації один: **«Із самого серця Карпат»**.
Він заданий у `src/content/brand.ts` і підставляється в усі розділи звідти —
щоб змінити формулювання довелось в одному місці, а розійтись воно не могло.

## Розробка

```bash
npm install
npm run dev        # http://localhost:5174
npm run typecheck
npm run build      # → dist/
npm run preview    # http://localhost:4173
npm run smoke      # перевірка сценаріїв у браузері; потрібен запущений preview
```

Для `smoke` потрібен браузер Playwright: `npx playwright install chromium`.

## Публікація

Портал збирається в GitHub Actions (`.github/workflows/deploy-pages.yml`) і
публікується в підкаталозі `/partner-portal/`. Зібрана версія також лежить у
репозиторії в каталозі `partner-portal/` — щоб портал відкривався навіть без
запуску збірки.

Base у Vite відносний (`./`), маршрутизація — на хешах: та сама збірка працює
і в підкаталозі GitHub Pages, і з файлової системи в нативній обгортці.

## Структура

```
src/
  content/
    brand.ts          сталі бренду: слоган, назва, гаряча лінія, сайт
    portal.ts         збірка розділів у портал
    sections/         по файлу на розділ — чисті дані, без JSX
  types/
    content.ts        модель блоків контенту
    catalog.ts        модель товару (без комерційної частини)
  data/
    skus.ts           18 позицій: штрих-коди, палетизація, габарити, вага
    glossary.ts       глосарій для партнерів і споживачів
  features/
    catalog/          полиця, каталог, картка товару
    calculators/      калькулятор палети й таблиці
    reference/        глосарій
    widgets.ts        реєстр віджетів, на які посилається контент
  components/         рендерер блоків, навігація, пошук, іконки
  styles/             дизайн-токени бренду й стилі
```

Контент — це дані, а не розмітка: розділ описується масивом блоків, тому пошук
будується автоматично (з блоків витягується чистий текст), а самі розділи можна
перенести в CMS без переписування коду.

## Як додати розділ

1. Створити файл у `src/content/sections/` за зразком сусідніх.
2. Вказати `group` — одну з `water`, `cooperation`, `partnership`, `info`.
3. Додати імпорт і сам розділ у масив `sections` у `src/content/portal.ts`.

Меню, шторка розділів, перехід «далі» й пошук підхоплять розділ самі.
