# Внутрішній портал ТМ «Трускавецька»

Довідник для працівників компанії: менеджерів з продажу й торгових
представників, комірників, водіїв і логістів. Один портал на всіх навмисно —
половина конфліктів між продажами й складом виникає тому, що кожен бачить
свою половину картини.

Зроблений на основі зовнішнього порталу для партнерів (`partner-portal-src`):
та сама дизайн-система, та сама модель контенту, ті самі віджети каталогу
й логістики. Відрізняється аудиторією і, головне, тим, що тут **є**.

## Що всередині

**Продукт** — формати й пакування (полиця в реальному масштабі, картки
позицій, ціни), три лінійки, склад і властивості води, джерело й Трускавець,
торговельне обладнання.

**Продажі** — прайс і дві цінові зони, калькулятор націнки точки, межі
повноважень менеджера, аргументація й дванадцять заперечень, межі
дозволеного в розмові про воду, чотири типи клієнтів, викладка й полиця,
цикл візиту зі збіркою замовлення.

**Склад і логістика** — приймання партії, зберігання й терміни з
калькулятором залишкового терміну, комплектація й відвантаження, транспорт
із калькулятором завантаження, повернення й брак, інвентаризація.

**Довідка** — якість і документи, довідник (штрих-коди, габарити,
палетизація, глосарій, скорочення), матеріали бренду, охорона праці,
контакти й служби.

## Чим відрізняється від зовнішнього порталу

Зовнішній портал побудований на правилі «нічого, що змінюється від дати чи
від контрагента». Внутрішній — на протилежному: саме те, що змінюється, тут
і потрібне.

Тому тут є прайс, націнки, межі повноважень, внутрішні регламенти й порядок
дій у нестандартних ситуаціях. Через це:

- у шапці замість слогана стоїть позначка **«Внутрішній документ»** — вона
  має бути перед очима щоразу, коли працівник показує екран у торговій точці;
- у розділах, де є ціни, стоять прямі нагадування, чого не можна показувати
  клієнту з екрана й пересилати назовні;
- сторінка закрита від індексації (`noindex` в `index.html`).

Зовнішній портал лишається тим, що дають клієнту: у ньому та сама
інформація про продукт, але без цін і внутрішніх матеріалів.

## Прайс

Ціни лежать в одному місці — `src/data/skus.ts`, поле `price` кожної позиції.
Ніде більше вони не дублюються: у текстах розділів цін немає навіть числами,
тільки посилання на таблицю й калькулятор.

Редакція прайсу задана однією константою `PRICE_REVISION` у
`src/content/brand.ts` і підставляється в усі місця, де показана ціна.
При оновленні прайсу правляться саме ці два файли — і дата змінюється всюди.

## Калькулятори

Шість інтерактивних модулів; п’ять із них рахують те, чого не було в
зовнішньому порталі.

| Модуль | Що рахує | Де стоїть |
| --- | --- | --- |
| `price-calculator` | Заробіток точки при РРЦ від бази з ПДВ або без: націнка, маржа, гривня з палети | Ціни й канали |
| `pallet-calculator` | Пляшки ↔ упаковки ↔ палети ↔ літри, вага, шари | Комплектація |
| `shelf-life` | Залишковий термін партії від дати розливу, пороги 1/2 і 2/3 | Зберігання |
| `load-calculator` | Скільки палет входить в авто — за вагою і за місцями | Транспорт |
| `order-mix` | Збірне замовлення по позиціях і клієнтах: пляшки, палетомісця, вага, сума | Візит і замовлення |
| `objections` | Дванадцять заперечень із відповідями | Аргументація |

Два з них варто пояснити окремо.

**`load-calculator`** показує дві межі одночасно, а не одну відповідь. Вода —
важкий вантаж: палета важить 600–800 кг, тому тент на 33 палетомісця
набирається за вагою приблизно на двадцять четвертій палеті, і третина
кузова їде порожньою. Хто цього не рахує — або возить повітря, або
перевантажує авто.

**`order-mix`** — єдиний віджет, за яким продажі й склад дивляться на одну
цифру: менеджер набирає замовлення й бачить суму, комірник за тим самим
переліком бачить пляшки, вагу й палетомісця. Три речі визначили його вигляд:

- рядок — це **позиція**, а не формат: негазована й сильногазована 0,5 л
  мають різні штрих-коди, і склад збирає саме їх;
- кількість — у палетах **або в упаковках**: точка замовляє упаковками,
  дистриб'ютор палетами, і перераховувати в голові посеред розмови ніхто не
  буде;
- машина возить **кількох клієнтів одразу**, тому підсумок є і по кожному,
  і загальний. Палетомісця рахуються по клієнтах, а не з загальної суми
  палет: позиції одного клієнта складають на спільну мікс-палету, чужий
  товар до них не домішують. Саме тут найчастіше й не сходиться те, що
  порахували продажі, з тим, що поставив у машину склад.

## Матеріали з Google Drive

Важкі файли — фото продукції й обладнання, бренд-гайд, специфікації,
фотоархіви — у бандл не потрапляють: 18 фото SKU важать понад 20 МБ. Портал
показує їх прямо з Drive через адресу прев'ю, тому тягне зменшені копії, а не
оригінали.

Якщо доступ до файлу закриють, сторінка не зламається: `DriveImage` пробує
другу адресу, а потім прибирає зображення, і картка лишається текстовою.

Ідентифікатори зібрані в трьох місцях: `src/content/assets.ts` (документи й
логотипи), `src/data/photos.ts` (фото SKU), `photoId` у `src/data/equipment.ts`.

## Розробка

```bash
npm install
npm run dev        # http://localhost:5175
npm run typecheck
npm run build      # → dist/
npm run build:demo # → dist-demo/index.html — усе одним самодостатнім файлом
npm run preview    # http://localhost:4173
npm run smoke      # перевірка сценаріїв у браузері; потрібен запущений preview
```

Для `smoke` потрібен браузер Playwright: `npx playwright install chromium`.
Перевірка не залежить від мережі: запити до Drive перехоплюються й
підмінюються зображенням-заглушкою.

Смоук перевіряє саме те, що відрізняє цей портал: що ціни показані й
згруповані по розрядах, що від бази без ПДВ націнка виходить вища, що термін
придатності рахується по-різному для газованого й негазованого ПЕТ і
закінчується на добу раніше за річницю розливу, що завантаження авто
впирається у вагу, що замовлення двох клієнтів на 6,28 палети займає сім
палетомісць, і що всі 23 розділи відкриваються.

## Публікація

Портал збирається в GitHub Actions (`.github/workflows/deploy-pages.yml`) і
публікується в підкаталозі `/employee-portal/`. Зібрана версія також лежить
у репозиторії в каталозі `employee-portal/` — щоб портал відкривався навіть
без запуску збірки.

Base у Vite відносний (`./`), маршрутизація — на хешах: та сама збірка працює
і в підкаталозі GitHub Pages, і з файлової системи в нативній обгортці.

Портал працює офлайн після першого відкриття — це не зручність, а умова
роботи: на складі, у кузові й на маршруті мережі часто немає, а довідник
потрібен саме там.

## Структура

```
src/
  content/
    brand.ts          сталі бренду, редакція прайсу, форма запиту, посилання
    assets.ts         посилання на файли й теки Google Drive
    portal.ts         збірка розділів у портал
    sections/         по файлу на розділ — чисті дані, без JSX
  types/
    content.ts        модель блоків контенту, групи й аудиторії розділів
    catalog.ts        модель товару разом із ціновою частиною
  data/
    skus.ts           18 позицій: штрих-коди, палетизація, габарити, ціни
    vehicles.ts       типові транспортні засоби: палетомісця й тоннаж
    objections.ts     дванадцять заперечень із відповідями
    photos.ts         фото кожної позиції — id файлів на Drive
    equipment.ts      11 позицій торговельного обладнання з габаритами
    glossary.ts       глосарій продажів, складу й документів
  features/
    catalog/          полиця, каталог, картка товару, мітка газації
    calculators/      палета, ціна, термін придатності, завантаження, замовлення
    equipment/        каталог обладнання із силуетами в одному масштабі
    reference/        глосарій і заперечення
    widgets.ts        реєстр віджетів, на які посилається контент
  components/         рендерер блоків, навігація, пошук, іконки, DriveImage
  styles/             дизайн-токени бренду й стилі
```

Контент — це дані, а не розмітка: розділ описується масивом блоків, тому пошук
будується автоматично (з блоків витягується чистий текст), а самі розділи можна
перенести в CMS без переписування коду.

## Як додати розділ

1. Створити файл у `src/content/sections/` за зразком сусідніх.
2. Вказати `group` — одну з `product`, `sales`, `warehouse`, `info`.
3. Вказати `audience` — `sales`, `warehouse` або `all`. Від цього залежить
   мітка в шторці розділів; розділи «для всіх» мітки не мають навмисно.
4. Додати імпорт і сам розділ у масив `sections` у `src/content/portal.ts`.

Меню, шторка розділів, перехід «далі» й пошук підхоплять розділ самі.
У `scripts/smoke.mjs` треба поправити очікувану кількість пунктів меню.
